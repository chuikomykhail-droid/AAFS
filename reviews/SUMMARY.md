# Сводный отчёт ревью проекта AAFS

## 1. Вердикт

Результатам бэктеста и ключевым выводам `README.md` можно доверять: конвейер полностью воспроизводим «бит в бит» (`max_abs_diff = 0.0`), граница обучения $t \le D - h$ математически строга, а все опубликованные метрики точно соответствуют расчётам по сохранённым таблицам прогнозов. Блокирующих ошибок для сдачи MVP нет: все 26 тестов проходят, утечек токенов API в репозитории нет, а преимущество LightGBM над базовыми частотами на основном горизонте $h = 3$ (+0.027 PR-AUC) и $h = 1$ (+0.036) статистически подтверждено. Вместе с тем ревью вскрыло важный концептуальный факт: превосходство ML над B1 на валидации обеспечивалось не сложными пространственными взаимодействиями, а адаптацией к дрейфу базовой частоты — экспоненциально взвешенный бейзлайн B1 (полураспад 28 дней) не уступает LightGBM на валидации (PR-AUC 0.698 против 0.695). На горизонте $h = 6$ выигрыш LightGBM статистически неустойчив при блочном бутстрепе ([+0.001, +0.031] при блоках 3 дня), а логистическая регрессия не даёт значимого преимущества над B1 на $h = 3$ и $h = 6$. Главные действия перед дедлайном — доложить обязательные артефакты (логи работы с ИИ и рефлексию), синхронизировать устаревшие формулировки в `PLAN.md` и `DECISIONS.md`, внести открытые особенности в раздел «Обмеження» `README.md` и применить точечные безопасные правки в коде без перезапуска тяжёлого 30-минутного бэктеста.

## 4. Текст для раздела «Обмеження» в README

```markdown
- **Перевага моделей і згасання пам'яті:** Значна частина переваги над B1 на валідації пояснюється
  експоненційним згасанням ваги спостережень (бейзлайн B1 із напіврозпадом 28 діб на валідації досягає
  PR-AUC 0.698 проти 0.695 у LightGBM). На тесті LightGBM зберігає статистично значущу перевагу при
  h = 1 (+0.036) та h = 3 (+0.027), але на h = 6 інтервал звужується ([+0.001, +0.031] при 3-добових
  блоках бутстрепу), а логістична регресія не має значущої переваги над B1 при h = 3 та h = 6.
- **Локальність часової дискримінації:** Модель надійно розрізняє моменти в часі у великих вузлах
  (Київ: PR-AUC 0.60–0.63 проти 0.34 у B1), однак у середньому по країні часова диференціація
  всередині окремого району є помірною (медіанний ROC-AUC у часі становить 0.617).
- **Втрачені тривоги правого краю (вечір 06.09):** Через зупинку каналу о 06:09 07.09 тривоги, що
  тривали довше кількох годин увечері 06 вересня, не встигли завершитися й не потрапили до CSV
  (дефіцит становить приблизно 35–40 позитивних міток на h = 3), що локально занижує тестові метрики.
- **Розбіжність між спостерігачем у реальному часі та сіткою:** У реальному часі спостерігач звертається
  за прогнозом, коли тривога не надходила > 24 год (за таблицею seen), тоді як сітка ретроспективно
  видаляє ці години за повною тривалістю сегмента (12 375 кандидатів).
- **Сліпі зони перевірок на витік:** Тест «псування майбутнього» (leakage.check) не виявляє витоків
  із лагом, меншим за горизонт прогнозу h (у межах 3 год), тому чистота ознак спирається на суворий
  knowledge_check та закритий інтерфейс AlertHistory.
- **Ретроспективні правки в API alerts.in.ua:** Перевірка knowledge_check на періоді API спирається
  на час завершення тривоги finished_at і не враховує запізнілі пакетні оновлення бази API (57 записів
  оновлено з затримкою > 1 год).
```
